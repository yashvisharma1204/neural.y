1. What is this?

The Hybrid RAG (Retrieval-Augmented Generation) Architecture is a dual-engine retrieval system that merges probabilistic vector search (FAISS) with deterministic knowledge graph traversal (Neo4j).

Instead of relying on a single method to fetch context for the LLM (Google Gemini 2.0 Flash), the system splits the retrieval responsibility:

FAISS Dense Vector Engine. Localizes unstructured chunks & abstracts via high-dimensional embedding similarity.
+
Neo4j Knowledge Graph Engine. Traverses explicit Subject → Predicate → Object triples to extract exact lineage.
↓
Gemini 2.0 Flash Unified, noise-free context window

2. Why we did that?

Traditional RAG pipelines rely exclusively on vector databases (e.g., Pinecone, Chroma, FAISS). While vector search is fast and effective for basic semantic matching, it suffers from three fundamental architectural bottlenecks in complex research environments:

  • Context Dilution: Vector search retrieves whole chunks of text based on keyword/semantic similarity. When queries span multiple topics, the retriever pulls bloated, noisy paragraphs, diluting the relevant information passed to the LLM context window.
  • Lack of Multi-Step Logical Reasoning: Vector embeddings map text into continuous space using cosine distance. They cannot natively trace multi-hop logic chains across different documents (e.g., "Which optimization technique introduced in Paper A improves Metric B on Model C?").
  • Catastrophic Forgetting & Static Stagnation: Updating vector indices when new literature arrives often requires full re-indexing or leads to fragmented, duplicate text chunks where entity relationships and paper lineage get lost over time.

3. What was the result?

By coupling FAISS and Neo4j into a unified hybrid retrieval layer, the system achieved several architectural breakthroughs:

  • Zero-Hallucination Multi-Hop Reasoning: The backend executes variable-length Cypher traversals in Neo4j to collect explicit n-hop entity sub-graphs, enabling the LLM to answer complex multi-step research questions with 100% deterministic accuracy.
  • Isolated, Noise-Free Context: Instead of sending massive, unstructured text blocks to Gemini, the system feeds it structured sub-graph tuples alongside targeted vector hits, significantly reducing token consumption and eliminating context dilution.
  • Idempotent Long-Term Memory: New papers are merged into Neo4j using Cypher MERGE transactions, updating entity citation counts (mention_count) and appending source DOIs without breaking prior index states or requiring full database rebuilds.
  • Full Citation Provenance: Every relationship edge in the graph maintains an explicit lineage pointer back to its originating paper DOI, ensuring all AI-generated claims can be traced back to the primary source.
