step 01

The Problem — Attention Has No Sense of Order

§3.5: "Since our model contains no recurrence and no convolution, in order for the model to make use of the order of the sequence, we must inject some information about the relative or absolute position of the tokens in the sequence."

Self-attention computes weighted sums over a set of vectors. Shuffle the input tokens and the output is shuffled the same way — the mechanism is permutation-equivariant. "the cat sat" and "sat cat the" would produce identical representations. Something must break that symmetry before the first layer.

Why not just recurrence? RNNs get order for free because they process tokens one after another. The Transformer threw out recurrence for parallelism — so it has to re-inject order explicitly. Positional encoding is the price paid for going fully parallel.

step 02

The Sinusoidal Formula

§3.5 defines the encoding for position $pos$ and dimension $i$:

$$PE_{(pos,\, 2i)} = \sin\!\left(\frac{pos}{10000^{2i/d_{\text{model}}}}\right), \qquad PE_{(pos,\, 2i+1)} = \cos\!\left(\frac{pos}{10000^{2i/d_{\text{model}}}}\right)$$

Each dimension of the encoding is a sinusoid. Even dimensions use sine, odd use cosine, and the wavelength grows geometrically from $2\pi$ up to $10000\cdot 2\pi$ as you move along the 512 dimensions. Low dimensions oscillate fast (fine position detail); high dimensions oscillate slowly (coarse position).

The Wavelength Ladder

The period of dimension pair $k$ is $\lambda_k = 2\pi \cdot 10000^{2k/d}$. It stretches geometrically from $2\pi \approx 6.28$ tokens at the fastest dimension to nearly $10000\cdot 2\pi$ at the slowest — over four orders of magnitude across the 512 dimensions:

$$\lambda_0 = 2\pi \approx 6.28 \quad\longrightarrow\quad \lambda_{255} = 2\pi\cdot 10000^{510/512} \approx 60{,}600$$

Binary-counter analogy, made precise In binary, bit 0 flips every 1 step, bit 1 every 2, bit 2 every 4 — geometric periods. Sinusoidal PE is the continuous version: dim 0 has period ~6.3, and each higher dimension multiplies the period by $10000^{2/d} \approx 1.037$. The whole 512-vector is a smooth, real-valued place-value code for position.

step 03

Why Sinusoids — The Relative-Position Trick

§3.5: "We chose this function because we hypothesized it would allow the model to easily learn to attend by relative positions, since for any fixed offset $k$, $PE_{pos+k}$ can be represented as a linear function of $PE_{pos}$."

This is the deep reason. Because of the angle-addition identities, shifting a position by a fixed offset $k$ is a linear (rotation) transform of the encoding — one that does not depend on $pos$ itself:

$$\begin{bmatrix} \sin(\omega(pos{+}k)) \\ \cos(\omega(pos{+}k)) \end{bmatrix} = \begin{bmatrix} \cos\omega k & \sin\omega k \\ -\sin\omega k & \cos\omega k \end{bmatrix} \begin{bmatrix} \sin(\omega\, pos) \\ \cos(\omega\, pos) \end{bmatrix}$$

So the model can learn a single weight matrix that means "look 3 tokens back" and apply it identically everywhere in the sequence. Relative position becomes a linear operation the attention layers can exploit directly.

step 04

Added, Not Concatenated

The encoding is added to the token embedding, keeping the width at $d_{\text{model}}$ (concatenation would double it). This is why §3.4's $\sqrt{d_{\text{model}}}$ scaling matters — it balances token identity against the positional signal before they are summed. §3.5 also notes dropout ($P_{drop}=0.1$) is applied to the sum before layer 1.

$$\text{input}_{pos} = E[t_{pos}]\cdot\sqrt{d_{\text{model}}} + PE_{pos}, \qquad X_0 = \text{Dropout}(\text{input})$$

PyTorch Implementation

class PositionalEncoding(nn.Module):
    def __init__(self, d_model=512, max_len=5000, dropout=0.1):
        super().__init__()
        self.dropout = nn.Dropout(dropout)
        pe = torch.zeros(max_len, d_model)
        pos = torch.arange(max_len).unsqueeze(1).float()            # [L, 1]
        # ω_i = 1 / 10000^(2i/d)  — computed in log space for stability
        div = torch.exp(torch.arange(0, d_model, 2).float()
                        * -(math.log(10000.0) / d_model))
        pe[:, 0::2] = torch.sin(pos * div)   # even dims → sin
        pe[:, 1::2] = torch.cos(pos * div)   # odd dims  → cos
        self.register_buffer('pe', pe.unsqueeze(0))  # not a parameter

    def forward(self, x):                       # x: [B, m, 512]
        x = x + self.pe[:, :x.size(1)]           # add, sliced to seq len
        return self.dropout(x)
Once at the bottom, that's it Positional encoding is added a single time, before layer 1 of each stack. It is not re-injected at every layer — the residual connections carry the positional signal upward through all $N$ layers on their own.
