step 01

What Attention Actually Computes

§3.2: "An attention function can be described as mapping a query and a set of key-value pairs to an output, where the query, keys, values, and output are all vectors. The output is computed as a weighted sum of the values, where the weight assigned to each value is computed by a compatibility function of the query with the corresponding key."

Strip away the matrices and it is one idea: for each query, look up how relevant every key is, turn those relevances into a probability distribution, then average the values under that distribution. Everything else in this section is how that lookup is made fast, stable, and expressive.

Q, K, V — one intuition The query is the current token asking a question. Each key is a token advertising what it contains. The dot product $q\cdot k$ measures how well the question matches that advertisement. The value is the actual content retrieved once you know how much to trust each match.

step 02 · §3.2.1

Scaled Dot-Product Attention

§3.2.1: "We compute the dot products of the query with all keys, divide each by $\sqrt{d_k}$, and apply a softmax function to obtain the weights on the values." Packed into matrices for a whole batch of queries at once:

Why divide by √d_k

§3.2.1: "We suspect that for large values of $d_k$, the dot products grow large in magnitude, pushing the softmax function into regions where it has extremely small gradients." The reasoning is statistical. If the components of $q$ and $k$ are independent with mean 0 and variance 1, then their dot product has mean 0 but variance $d_k$:

$$q\cdot k = \sum_{i=1}^{d_k} q_i k_i, \qquad \mathbb{E}[q\cdot k] = 0, \qquad \text{Var}(q\cdot k) = d_k$$

So the raw scores have standard deviation $\sqrt{d_k}$. With $d_k = 64$ that is a spread of $\pm 8$ — large enough that softmax saturates, one weight goes to ~1 and the rest to ~0, and gradients through the other terms vanish. Dividing by $\sqrt{d_k}$ renormalises the variance back to 1, keeping the distribution soft and the gradients healthy.

Dot-product vs. additive attention §3.2.1 notes additive attention (a small feed-forward net, à la Bahdanau) and dot-product attention have similar theoretical cost, "but dot-product attention is much faster and more space-efficient in practice, since it can be implemented using highly optimized matrix multiplication code." The scaling is the one fix that lets the fast version match the additive version's stability at large $d_k$.

Worked Example — one query, three keys

Say a query scores $[6.0, 2.0, 4.0]$ against three keys, with $d_k = 4$ so $\sqrt{d_k} = 2$:

$$\tfrac{S}{\sqrt{d_k}} = [3.0,\, 1.0,\, 2.0] \ \xrightarrow{\text{softmax}}\ [0.665,\, 0.090,\, 0.245]$$ $$o = 0.665\,v_1 + 0.090\,v_2 + 0.245\,v_3$$

Without the scale the raw scores $[6,2,4]$ soften to $[0.867, 0.016, 0.117]$ — far peakier. The $\sqrt{d_k}$ divide is what keeps positions 2 and 3 from being effectively ignored.

step 03 · §3.2.2

Multi-Head Attention — Doing It Eight Ways

§3.2.2: "Instead of performing a single attention function with $d_{\text{model}}$-dimensional keys, values and queries, we found it beneficial to linearly project the queries, keys and values $h$ times with different, learned linear projections... On each of these projected versions we then perform the attention function in parallel."

A single attention head can only express one notion of relevance at a time — its softmax has to commit to one weighting. Multiple heads let the model attend to different things simultaneously: one head might track syntactic dependencies, another positional adjacency, another coreference.

$$\text{head}_i = \text{Attention}(QW_i^Q,\, KW_i^K,\, VW_i^V)$$ $$\text{MultiHead}(Q,K,V) = \text{Concat}(\text{head}_1, \ldots, \text{head}_h)\,W^O$$

Each head gets its own learned projections down to $d_k = d_v = d_{\text{model}}/h = 64$ dimensions, runs scaled dot-product attention in that subspace, and the eight 64-dim outputs are concatenated back to 512 and mixed by $W^O$:

$$W_i^Q, W_i^K \in \mathbb{R}^{512\times 64}, \quad W_i^V \in \mathbb{R}^{512\times 64}, \quad W^O \in \mathbb{R}^{512\times 512}$$

Labels are illustrative only — the paper assigns heads no fixed jobs. These names are a mnemonic; real heads learn overlapping, often uninterpretable mixes, and some are redundant enough to prune after training.

The cost stays flat — §3.2.2 "Due to the reduced dimension of each head, the total computational cost is similar to that of single-head attention with full dimensionality." Because $h \cdot d_k = 8 \cdot 64 = 512 = d_{\text{model}}$, eight heads at width 64 cost about the same as one head at width 512 — you get diversity for free, not by spending more compute.
The catch — quadratic in sequence length "Free" refers to head width, not sequence length. The score matrix $QK^\top$ is $n \times n$ per head, so both compute and memory scale as $O(n^2 \cdot d)$ — double the sequence and you quadruple the attention cost. This is the single biggest scaling bottleneck of the vanilla Transformer and the motivation behind later work (sparse, linear, and flash attention). §4 gives the exact per-layer complexity table.

step 04 · §3.2.3

Three Ways the Transformer Uses Attention

§3.2.3: "The Transformer uses multi-head attention in three different ways." The mechanism is identical every time — only where $Q$, $K$, and $V$ come from changes, and whether a mask is applied.

1 — Encoder Self-Attention

$Q, K, V$ all come from the previous encoder layer. Every source position attends to every source position — no mask.

$\text{MHA}(X, X, X)$
2 — Masked Decoder Self-Attn

$Q, K, V$ from the decoder itself, but a causal mask blocks $j > i$ to preserve the auto-regressive property.

$\text{MHA}(Y, Y, Y) + \text{mask}$
3 — Encoder-Decoder Cross-Attn

$Q$ from the decoder, $K, V$ from the encoder output. Every target position attends over all source positions.

$\text{MHA}(Y, Z, Z)$

Decoder self-attndecoder layerdecoder layercausal$m \times m$
Cross-attndecoder layerencoder outputno$m \times n$
Same block, different wiring This is the elegance of the architecture: one MultiHeadAttention module, reused three times. Encoder and decoder look different only because of what you feed the same primitive and whether you hand it a mask.

step 05

PyTorch Implementation

The whole of §3.2 fits in one module. Note the reshape trick: instead of eight separate matmuls, project once to 512, split into $(h, d_k)$, and let batched matrix multiply handle all heads at once.

import torch, torch.nn as nn, torch.nn.functional as F

def scaled_dot_product_attention(Q, K, V, mask=None):
    d_k = Q.size(-1)
    scores = Q @ K.transpose(-2, -1) / d_k ** 0.5      # [B, h, m, n]
    if mask is not None:
        scores = scores.masked_fill(mask == 0, float('-inf'))
    attn = F.softmax(scores, dim=-1)                    # rows sum to 1
    return attn @ V, attn                              # [B, h, m, d_v]

class MultiHeadAttention(nn.Module):
    def __init__(self, d_model=512, num_heads=8):
        super().__init__()
        assert d_model % num_heads == 0
        self.h, self.d_k = num_heads, d_model // num_heads   # 8, 64
        self.W_q = nn.Linear(d_model, d_model)               # all heads at once
        self.W_k = nn.Linear(d_model, d_model)
        self.W_v = nn.Linear(d_model, d_model)
        self.W_o = nn.Linear(d_model, d_model)               # output mix

    def forward(self, q, k, v, mask=None):
        B = q.size(0)
        # project, then split 512 → (h=8, d_k=64) and swap to [B, h, len, d_k]
        q = self.W_q(q).view(B, -1, self.h, self.d_k).transpose(1, 2)
        k = self.W_k(k).view(B, -1, self.h, self.d_k).transpose(1, 2)
        v = self.W_v(v).view(B, -1, self.h, self.d_k).transpose(1, 2)

        out, attn = scaled_dot_product_attention(q, k, v, mask)

        # concat heads back to 512, then final linear W^O
        out = out.transpose(1, 2).contiguous().view(B, -1, self.h * self.d_k)
        return self.W_o(out)                             # [B, m, 512]
Where the three uses call this Encoder self-attn: mha(x, x, x). Masked decoder self-attn: mha(y, y, y, causal_mask). Cross-attn: mha(y, enc_out, enc_out). One class, three call sites — exactly what §3.2.3 describes.

Attention in one expression $$\text{MultiHead}(Q,K,V) = \Big[\,\text{softmax}\!\big(\tfrac{QW_i^Q (KW_i^K)^\top}{\sqrt{d_k}}\big)VW_i^V\,\Big]_{i=1}^{h}\,W^O$$ Every attention block in both the encoder and decoder is exactly this, differing only in the source of $Q,K,V$ and the presence of a mask.
Attention at inference — the KV-cache During autoregressive generation the decoder produces one token at a time, and its masked self-attention re-attends over the entire prefix at every step. Recomputing all past keys and values each step would cost $O(n^2)$ work to emit $n$ tokens. Because past positions are fixed once generated, implementations cache their $K$ and $V$ projections and only compute $K,V$ for the newest token — so each step is $O(n)$ and the whole sequence is $O(n^2)$ instead of $O(n^3)$. The paper doesn't describe this (it's an inference-time engineering detail), but it's why Transformer generation is practical. Note: cross-attention's $K,V$ come from the fixed encoder output, so they're computed once and cached for the entire decode.
Why this replaces recurrence A single attention layer connects any two positions in $O(1)$ sequential steps — no unrolling through time. That constant path length, plus the fully parallel matmul form, is what lets the Transformer drop recurrence entirely. §4 quantifies exactly this trade-off.
