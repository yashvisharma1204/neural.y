1. What is this?

The OpenIE (Open Information Extraction) Filtering Pipeline is an automated quality-control gate implemented on parsed Subject → Predicate → Object knowledge triples prior to graph database persistence.

Instead of blindly writing every extracted relation into the knowledge store, the ingestion engine evaluates confidence metrics to filter out superficial co-occurrences and model artifacts:

LLM / OpenIE Extracts raw SPO triples with confidence score c.
→
Threshold Gate Evaluates condition c ≥ τ to prune noise.
→
Neo4j Graph Persists high-signal, clean semantic relationships.

2. Why we did that?

Large Language Models and traditional OpenIE extractors are inherently susceptible to generation noise, resulting in severe data quality hurdles during automated knowledge graph construction:

  • Spurious Co-occurrences: Unchecked extractors frequently generate vague or generic relational links (e.g., paper → related_to → method) that add zero structural value to multi-hop reasoning.
  • Hallucinated Entities: Sub-optimal prompt parsing or low-probability token outputs can introduce fictitious parameter dimensions or non-existent benchmark datasets.
  • Graph Pollution: Unfiltered persistence bloats the Neo4j schema with redundant or low-confidence edges, ultimately degrading downstream RAG context quality and increasing token overhead.

3. What was the result?

Enforcing strict threshold-based filtering yielded immediate improvements across the entire data ingestion and retrieval workflow:

  • OpenIE Noise & Hallucination Filtering: Implemented threshold-based filtering (c ≥ τ) on parsed Subject-Predicate-Object knowledge triples to prune extraction noise and hallucinations prior to database persistence.
  • Higher Semantic Density: Only high-confidence edges enter the graph topology, ensuring multi-hop Cypher traversals remain precise and contextually relevant.
  • Optimized Storage Efficiency: Drastically reduced database write operations for redundant or junk triples, keeping the Neo4j memory footprint lean.
  • Deterministic RAG Reliability: Eliminated garbage-in-out failure modes, allowing Gemini 2.0 Flash to operate strictly over verified, clean knowledge paths.
